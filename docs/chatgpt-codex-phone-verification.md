# ChatGPT / Codex 桌面端要求验证手机号收不到码？2026 深度排查指南

> 适用场景：Codex CLI 首次 OAuth 登录、ChatGPT 桌面端触发二次安全核验、OpenAI 开发者后台绑定手机时提示 `Unsupported phone number` 或迟迟收不到短信验证码。

## 一、底层风控逻辑解析

OpenAI 在 2026 年进一步收紧了开发者与桌面端权限的短信风控策略，核心校验维度包括：

1. **号段信誉库（Carrier Lookup）**：自动识别并拒绝绝大多数 VOIP 虚拟号段（如 Google Voice、TextNow、部分云通讯虚拟号）以及已被高频复用的免费在线接码池。
2. **网络一致性（IP / Session Alignment）**：当浏览器与终端 CLI 走不同国家的代理出口，或者登录 IP 属于高并发万人共享机房时，系统会提高验证门槛甚至直接丢弃短信下发请求。
3. **重发冷却（Rate Limiting）**：10 分钟内连续点击超过 3 次 `Resend code`，账号会被静默加入 24 小时短信冷却名单。

---

## 二、4 步标准化排查流程

### Step 1：立即停止连点，确认冷却状态
如果刚才已经连续尝试超过 3 次未收到短信，请立即关闭验证窗口，等待至少 2 小时（若提示 `Too many requests` 则需等待完整 24 小时）。

### Step 2：对齐浏览器与终端网络出口
很多开发者在浏览器端开启了美国节点，但终端运行 `codex` 时没有配置代理环境变量，导致 OAuth 回调与 API 请求落入直连或不同地区节点。

```bash
# macOS / Linux 终端临时对齐代理端口（示例端口 7890）
export HTTP_PROXY="http://127.0.0.1:7890"
export HTTPS_PROXY="http://127.0.0.1:7890"

# 验证出口 IP 是否与浏览器一致
curl -s https://api.ipify.org
```

### Step 3：选用纯净实体运营商号段
- 避免使用免费网页接码网站（号码已被成千上万人复用，极易导致账号刚验证就被 `deactivated`）。
- 优先使用对应支持区的真实实体 SIM 卡号段（例如美国实体卡号段验证成本通常在 ¥2.2–¥3.5 级），输入号码时注意核对国家区号（如 `+1`），不要重复输入多余的 `0`。
- 配合具有长期正常使用记录、开启了两步验证的精养 Google Gmail 邮箱，可显著降低二次触发短信校验的概率。

### Step 4：先网页端完成绑定，再回到 CLI
不要直接在桌面端弹窗或 CLI 回调中反复死磕：
1. 打开浏览器无痕窗口，登录 `platform.openai.com` 或 `chatgpt.com`。
2. 在网页端完成手机号验证并确认账号状态正常。
3. 回到终端重新执行 Codex 登录授权流程。

## 三、常见异常问答

- **Q：收到验证码输入后提示 `Code expired or invalid`？**  
  A：检查本机系统时间是否准确（建议开启自动网络对时），并确保输入验证码期间代理节点没有断开重连。
- **Q：一个实体手机号可以验证几个账号？**  
  A：OpenAI 对单号码绑定次数限制极严（通常仅限 1–2 个账号），切勿用同一号码批量注册。
- **Q：Codex 赠送额度用完后怎么补充？**  
  A：可在确认账号安全稳定后按需补充官方 Codex Credits 额度（常见档位 250 / 1000 / 2500 额度）。
